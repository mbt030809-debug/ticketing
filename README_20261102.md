# ticketing — 쿠팡/N+ 앱 선착순 쿠폰 매크로 (2026-11-02)

폰(안드로이드) 앱의 쿠폰 받기 버튼을 오픈 시각에 맞춰 누른다. 두 가지 형태:

| 형태 | 위치 | 특징 |
|---|---|---|
| **APK (폰 단독)** | `android/` | PC 불필요. 접근성 서비스로 앱 실행·클릭 |
| Python (PC + ADB) | `ticketing/` | PC 에서 uiautomator2 로 폰 제어 |

## APK
- 빌드: GitHub Actions `build-apk` (push 시 자동 / Actions 탭에서 수동 실행) → Artifacts 의 `couponmacro_<날짜>.apk`
- 로컬 빌드: `cd android && ./gradlew assembleDebug` (Android SDK 필요) → `app/build/outputs/apk/debug/app-debug.apk`
- 설치: 폰에서 APK 설치(출처 불명 앱 허용) → 앱 실행 → [접근성 설정 열기]에서 '쿠폰 매크로' 켜기
  - 안드로이드 13+ 에서 서비스가 회색이면: [앱 정보 열기] → ⋮ → '제한된 설정 허용'
- 사용 (메인 화면: 이벤트 → 회차 → 가는 길 → 시작)
  1. 이벤트 선택(쿠팡 / N+) — N+ 앱은 설치된 앱 이름에서 자동 선택, 안 되면 [대상 앱 변경]
  2. **회차 시각**: 매일 12:00 · 18:00 · 24:00(자정)이 기본. 2개든 4개든 [＋ 시각 추가]로 자유롭게 추가·✕로 삭제하고, 체크로 켜고 끈다(초 단위도 가능: `11:59:59`).
     - **자동 실행**: 체크하면 켜진 시각마다 **매일 자동 실행**. 회차 1분 전(고급 설정에서 20~600초로 변경)에 **알람**(소리+진동+화면 켜기)이 울리면 화면 잠금을 풀어 두기만 하면 된다. 잠금이 풀리면 앱 실행 → 경로 이동 → 오픈 시각 클릭. 오픈 35초 전까지 잠겨 있으면 한 번 더 재촉하고, 8초 전까지 안 풀리면 그 회차는 건너뜀.
     - 재부팅·앱 업데이트 후에는 알람이 자동으로 다시 등록됨. 접근성 서비스가 켜져 있어야 하고, 배터리 설정에서 이 앱을 '제한 없음'으로 두는 것을 권장.
     - 같은 시각에 두 이벤트(쿠팡·N+)가 겹치면 먼저 시작된 하나만 실행됨.
  3. **쿠폰 페이지 가는 길 기록 (최초 1회)**: [● 경로 기록] → 대상 앱이 첫 화면으로 열림 → 쿠폰 페이지까지 평소처럼 눌러 이동 → 화면 위 [■ 기록 끝] (쿠폰 받기 버튼은 누르지 않기). 누른 버튼의 문구가 '이동 단계'로 저장되고, 시작할 때 같은 순서로 자동 이동한다. (닫기/나중에 같은 팝업 버튼은 '없어도 진행'으로 저장)
  - **화면 로딩 대기**: 앱 실행·이동 단계·새로고침 뒤에는 화면 로딩(로딩 표시/내용 변화)이 끝나 1초간 안정될 때까지 기다린 뒤에 다음 단계·쿠폰 선택을 한다(최대 15초, 초과 시 그대로 진행). 쿠폰 목록 읽기 전에도 동일.
  4. **받을 쿠폰 정하기 (필수)**: 모든 쿠폰을 받는 게 아니라 정한 쿠폰의 버튼만 누른다. [화면에서 고르기] → 대상 앱이 열리고(기록한 경로로 이동) 쿠폰 페이지에서 화면 위 [쿠폰 목록 읽기] → 보이는 쿠폰 카드가 목록으로 나오면 받을 것만 체크 → [선택 완료]. 직접 적으려면 쿠폰 카드에 적힌 문구를 한 줄에 하나씩(예: `5,000원 할인`), 비슷한 쿠폰이 있으면 `+`로 이어 구분(예: `5,000원+3만원 이상`). 정하지 않으면 시작되지 않는다.
     - **글자 없는 이미지 쿠폰**(카드 전체가 그림이라 문구로 못 찾는 경우): [화면에서 고르기] → 쿠폰 페이지에서 화면 위 **[위치로 찍기]** → 받을 카드를 직접 터치(여러 장 가능) → [완료]. 터치 위치 바로 위의 유일한 문구(예: `오후 5시 오픈`)를 기준점으로 삼아 `위치:오후 5시 오픈|35,120|…` 형태로 저장하므로 페이지가 조금 밀려도 같은 카드를 누른다. 기준 문구가 안 보이면 누르지 않음. 페이지를 스크롤하지 않은 첫 화면에서 보이는 카드만 지정할 것.
       결과 판별: 토스트, 또는 클릭 전에 없던 새 문구("발급/이미 받/마감" 등). 최대 60회 탭 후 중단. [진단 도구 → 찾기만]에서는 누를 위치에 초록 점만 표시하니 본 실행 전에 확인 권장.
     - 동작(글자 있는 쿠폰): 문구가 들어 있는 **카드 안의** 받기 버튼만 클릭 → 그 카드에 "받기 완료/이미 받은/소진" 등이 보이면 정리. 여러 개를 골랐으면 전부 정리될 때까지 반복.
     - 안전장치: 카드 범위(화면 높이의 45%)를 넘는 영역의 버튼은 누르지 않음, 카드에 버튼이 여러 개라 구분이 안 되면 누르지 않고 로그에 안내. [고급 설정 → 진단 도구 → 찾기만]으로 실제 화면에서 맞는 카드가 잡히는지 미리 확인할 것.
  5. 회차 몇 분 전에 **[▶ 예약 시작]** (화면 켜 둠, 잠금 해제; 실행 중에는 같은 버튼이 [■ 중지]로 바뀜). 자동 실행을 켜 뒀다면 이 버튼을 누르지 않아도 알람 후 자동으로 진행. 앱 실행 → 경로 자동 이동 → 오픈 3초 전 새로고침 → 오픈 시각에 클릭
  - 문구 없는 아이콘 버튼은 기록되지 않음 → 로그에 "건너뜀"이 뜨면 [고급 설정 → 이동 단계]에 직접 문구를 추가하거나 직접 이동해 두기
  - **클릭 확인**: 클릭이 나가면 그 자리에 빨간 점이 잠깐 뜸 (이동 단계·팝업 닫기 포함). [찾기만]은 누를 위치에 초록 점만 표시. [고급 설정]에서 끌 수 있음.
  - 쿠폰을 못 찾으면 로그에 이유가 남음(문구가 화면에 없음 / 기준 문구가 안 보임 / 읽히는 문구 목록). 화면을 아래로 당겨 새로고침하는 동작은 예약 실행에서만 한다. 경로를 기록하지 않았다면 예약 실행도 앱을 다시 시작하지 않고 지금 화면에서 이어서 진행.
  - 문구가 안 맞으면: [고급 설정 → 진단 도구 → 5초 뒤 화면 요소 보기] → [로그]에서 실제 문구 확인 → [고급 설정]에 반영
  - 메인 화면 버튼은 두 개: **[▶ 예약 시작]**(다음 회차 시각에 맞춰 대기 후 클릭) / **[⚡ 즉시 실행 (테스트)]**(앱을 다시 시작하지 않고 **지금 보던 화면**에서 대기 없이 바로 시도, 경로 이동 없음 — 쿠폰 페이지를 연 채로 누르고 상시 받을 수 있는 쿠폰으로 연습). 클릭 없이 위치만 확인하는 [찾기만]은 고급 설정의 진단 도구에 있음.
  - 회차 시각 직후 2분 이내에 시작하면 그 회차를 바로 시도, 그 이후엔 다음 회차로 넘어감
- **설정 자동 저장**: 이벤트(쿠팡/N+)별로 따로 저장되고, 앱을 닫거나 업데이트해도 유지됨. [고급 설정 → 이 이벤트 설정 초기화]로 기본값 복원.
- **앱 내 업데이트**: 앱 시작 시 자동 확인 + [업데이트 확인] 버튼 → 새 빌드가 있으면 변경 내용(커밋 메시지) 표시 → [업데이트] → 다운로드 → 설치 확인 화면
  - 배포 방식: push 시 CI 가 서명된 APK 를 GitHub Release(`build-<번호>`, 최근 5개 유지)로 게시. 앱은 최신 릴리스의 빌드 번호(=versionCode)와 비교.
  - **서명 키는 CI가 알아서 관리**: 첫 빌드에서 키를 만들어 저장소의 **비공개 초안 릴리스**(`signing-key (private)`, 쓰기 권한자만 보임)에 보관하고 이후 빌드마다 같은 키를 복원해 서명한다. 이 초안은 **삭제/게시하지 말 것**(삭제하면 이후 업데이트 불가). 원하면 Secrets(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`)로 직접 지정할 수도 있다(Secrets 우선).
  - **처음 한 번만**: 이전에 설치한 APK(Actions 아티팩트)는 서명 키가 매번 달라서 덮어쓸 수 없다 → 앱 삭제 후 [릴리스 페이지](https://github.com/mbt030809-debug/ticketing/releases/latest)의 APK 로 새로 설치. 그 뒤로는 앱 안에서 업데이트된다. (삭제하면 저장된 설정이 지워짐)
  - 업데이트 실패 시 원인(서명 불일치/저장 공간/차단 등)을 토스트와 로그에 풀어서 표시.
  - 저장소가 비공개로 바뀌면 인증 없는 조회가 막혀 앱 내 업데이트가 동작하지 않음.
  - 작업(예약) 실행 중에는 업데이트 불가.
- 동작: 앱 실행 → 이동 단계 클릭 → NTP 보정 후 오픈 시각 대기 → 버튼 반복 클릭 → 성공/소진 문구·토스트 감지 → 알림
- 한계: 이미지/캔버스 버튼은 문구 매칭이 안 되므로 [위치로 찍기]를 사용(화면이 바뀌면 다시 지정 필요). 서버 병목·재고 소진은 속도로 해결 불가.

## Python (PC + ADB)

폰 앱을 PC 에서 ADB/uiautomator2 로 제어한다.

## 전제 / 주의
- 본인 계정 1개, 본인 실기기. 에뮬레이터는 앱이 막을 수 있음 (우회 기능 없음).
- 캡차·본인인증 화면이 뜨면 수동 처리 (자동 우회 없음).
- 쿠팡·네이버 약관상 자동화 제한 가능 → 계정 제재 책임은 사용자 몫.
- 이 저장소의 selector/문구/경로는 **placeholder**. 실기기에서 확인해서 채워야 동작함.

## 준비 (PC)
1. 폰: 개발자 옵션 → USB 디버깅 ON (또는 무선 디버깅), 쿠팡/N+ 앱 로그인 상태 유지, 화면 자동 꺼짐 해제
2. PC: `adb` 설치, `pip install -r requirements.txt`
3. `adb devices` 로 연결 확인 (여러 대면 `--serial`)

## 사용
```bash
python -m ticketing ntp                          # PC 시계 오차 확인
python -m ticketing packages naver               # N+ 앱 패키지명 찾기
python -m ticketing inspect --clickable          # 현재 화면 요소 → selector 작성용
# config/events_20261102.yaml 편집 (package, pre_steps, target, 결과 문구, open_at)
python -m ticketing run config/events_20261102.yaml --event coupang_wowday --dry-run   # 타겟 탐색만
python -m ticketing run config/events_20261102.yaml --event coupang_wowday --now       # 리허설 (즉시 클릭)
python -m ticketing run config/events_20261102.yaml --event coupang_wowday             # 본 실행 (오픈 시각 대기)
```

## 설정 요령
- `lead_ms`: 탭 지연 보정. 리허설 로그로 조정 (너무 크면 오픈 전 클릭).
- 타겟 selector 가 오픈 전 버튼("오픈 예정")과 겹치지 않게 지정 → 활성 버튼 문구만 매칭.
- 결과 문구(`success_texts` 등) 미설정 시 클릭 1회 후 종료.
- 스크린샷/로그: `logs/<이벤트>_<상태>_<YYYYMMDD>_<HHMMSS>.png`
- 알림: 터미널 벨, `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` 설정 시 텔레그램

## 한계
