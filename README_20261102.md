# ticketing — 쿠팡/N+ 앱 선착순 쿠폰 매크로 (2026-11-02)

폰(안드로이드) 앱의 쿠폰 받기 버튼을 오픈 시각에 맞춰 누른다. 두 가지 형태:

| 형태 | 위치 | 특징 |
|---|---|---|
| **APK (폰 단독)** | `android/` | PC 불필요. 접근성 서비스로 앱 실행·클릭 |
| Python (PC + ADB) | `ticketing/` | PC 에서 uiautomator2 로 폰 제어 |

## APK
- 빌드: GitHub Actions `build-apk` (push 시 자동 / Actions 탭에서 수동 실행) → Artifacts 의 `couponmacro_<날짜>.apk`
- 로컬 빌드: `cd android && ./gradlew assembleDebug` (Android SDK 필요) → `app/build/outputs/apk/debug/app-debug.apk`
- 설치: 폰에서 APK 설치(출처 불명 앱 허용) → 앱 실행 → [접근성 설정 열기]에서 '쿠폰 매크로' 켜기
  - 안드로이드 13+ 에서 서비스가 회색이면: [앱 정보 열기] → ⋮ → '제한된 설정 허용'
- 사용 (메인 화면: 이벤트 → 회차 → 가는 길 → 시작)
  1. 이벤트 선택(쿠팡 / N+) — N+ 앱은 설치된 앱 이름에서 자동 선택, 안 되면 [대상 앱 변경]
  2. **회차 시각**: 매일 12:00 · 18:00 · 24:00(자정)이 기본. 2개든 4개든 [＋ 시각 추가]로 자유롭게 추가·✕로 삭제하고, 체크로 켜고 끈다(초 단위도 가능: `11:59:59`).
     - **자동 실행**: 체크하면 켜진 시각마다 **매일 자동 실행**. 회차 1분 전(고급 설정에서 20~600초로 변경)에 **알람**(소리+진동+화면 켜기)이 울리면 화면 잠금을 풀어 두기만 하면 된다. 잠금이 풀리면 오픈 5초 전에 앱 실행 → 정각에 경로 이동 → 쿠폰 받기. 오픈 35초 전까지 잠겨 있으면 한 번 더 재촉하고, 8초 전까지 안 풀리면 그 회차는 건너뜀.
     - 재부팅·앱 업데이트 후에는 알람이 자동으로 다시 등록됨. 접근성 서비스가 켜져 있어야 하고, 배터리 설정에서 이 앱을 '제한 없음'으로 두는 것을 권장.
     - 같은 시각에 두 이벤트(쿠팡·N+)가 겹치면 먼저 시작된 하나만 실행됨.
  3. **쿠폰 페이지 가는 길 기록 (최초 1회)**: [● 경로 기록] → 대상 앱이 첫 화면으로 열림 → 쿠폰 페이지까지 평소처럼 눌러 이동 → 화면 위 [■ 기록 끝] (쿠폰 받기 버튼은 누르지 않기). 누른 위치·스와이프가 '이동 단계'로 저장되고, 시작할 때 같은 순서로 자동 이동한다. (닫기/나중에 같은 팝업 버튼은 '없어도 진행'으로 저장)
  - **화면 로딩 대기**: 앱 실행·이동 단계·새로고침 뒤에는 화면 로딩(로딩 표시/내용 변화)이 끝나 1초간 안정될 때까지 기다린 뒤에 다음 단계·쿠폰 선택을 한다(이동 단계는 최대 6초·앱 시작은 10초, 초과 시 그대로 진행; 카운트다운 같은 숫자 문구는 판정에서 제외). 쿠폰 목록 읽기 전에도 동일.
  4. **받을 쿠폰 정하기 (필수)**: 모든 쿠폰을 받는 게 아니라 정한 쿠폰의 버튼만 누른다. [화면에서 고르기] → 대상 앱이 열리고(기록한 경로로 이동) 쿠폰 페이지에서 화면 위 [쿠폰 목록 읽기] → 보이는 쿠폰 카드가 목록으로 나오면 받을 것만 체크 → [선택 완료]. 직접 적으려면 쿠폰 카드에 적힌 문구를 한 줄에 하나씩(예: `5,000원 할인`), 비슷한 쿠폰이 있으면 `+`로 이어 구분(예: `5,000원+3만원 이상`). 정하지 않으면 시작되지 않는다.
     - **글자 없는 이미지 쿠폰**(카드 전체가 그림이라 문구로 못 찾는 경우): [화면에서 고르기] → 쿠폰 페이지에서 화면 위 **[위치로 찍기]** → 받을 카드를 직접 터치(여러 장 가능) → [완료]. 터치 위치 바로 위의 유일한 문구(예: `오후 5시 오픈`)를 기준점으로 삼아 `위치:오후 5시 오픈|35,120|…` 형태로 저장하므로 페이지가 조금 밀려도 같은 카드를 누른다. 기준 글자가 접근성에 안 보이면(이미지 화면 등) 찍은 **화면 비율 위치로 바로 탭**(예약 실행은 기준 글자를 3번 확인해 본 뒤, 테스트는 즉시). 예전 빌드에서 OCR 로 저장된 위치도 같은 방식으로 동작. 페이지를 스크롤하지 않은 첫 화면에서 보이는 카드만 지정할 것.
       결과 판별: 토스트, 또는 클릭 전에 없던 새 문구("발급/이미 받/마감" 등). 최대 60회 탭 후 중단. [진단 도구 → 찾기만]에서는 누를 위치에 초록 점만 표시하니 본 실행 전에 확인 권장.
     - 동작(글자 있는 쿠폰): 문구가 들어 있는 **카드 안의** 받기 버튼만 클릭 → 그 카드에 "받기 완료/이미 받은/소진" 등이 보이면 정리. 여러 개를 골랐으면 전부 정리될 때까지 반복.
     - 안전장치: 카드 범위(화면 높이의 45%)를 넘는 영역의 버튼은 누르지 않음, 카드에 버튼이 여러 개라 구분이 안 되면 누르지 않고 로그에 안내. [고급 설정 → 진단 도구 → 찾기만]으로 실제 화면에서 맞는 카드가 잡히는지 미리 확인할 것.
  5. 회차 몇 분 전에 **[▶ 예약 시작]** (화면 켜 둠, 잠금 해제). **한 번 실행하고 끝나지 않는다** — 누르면 다음 회차를 지금 예약하고 '예약 켜짐(자동 실행)'도 함께 켜서, 이후 켜진 회차(12·18·24시 등)를 매일 이어서 실행한다(회차 1분 전 알람 → 잠금만 풀면 됨). 예약이 켜져 있는 동안 같은 버튼은 **[■ 예약 중지]**: 지금 작업과 이후 예약을 모두 끈다. 이미 [예약 시작]으로 실행 중인 회차는 알람이 중복으로 시작하지 않는다. **오픈 5초 전 앱 실행 → 오픈 정각에 경로 이동 → 쿠폰 받기** (앱 실행 시점은 고급 설정 '앱 실행 시점'(기본 5초 전)에서 변경. '경로 이동을 오픈 정각에 시작'을 끄면 예전 방식: 미리 이동해 두고 오픈 3초 전 새로고침 후 대기)
  - **경로 = 내가 한 터치(탭·스와이프·길게 누르기)를 그대로 기억해 재생**: [경로 기록] 중에는 화면 전체를 이 앱의 투명 창이 먼저 받아 터치 위치/움직임/이전 동작 후 흐른 시간을 저장하고, 같은 동작을 아래 앱에 대신 전달한다. 앱이 버튼 클릭 신호를 주지 않거나(N+ 앱 등) 페이지가 바뀌지 않아도 기록된다. 이동 단계 형식: 탭 `@0.50,0.90~1200`, 길게 `@0.50,0.90#800`, 스와이프(스크롤) `S@0.50,0.70>0.50,0.30#350`. 시작하면 같은 동작을 같은 순서로 한다. **원하는 화면이 나왔을 때 누른다**: [경로 기록] 중 탭/스와이프 직전 화면(칸별 밝기 24×40 격자, 글자와 무관 — 이미지 화면도 가능)을 **기준 화면(◎)**으로 함께 저장하고, 마지막으로 [■ 기록 끝]을 누른 순간의 화면(쿠폰을 고를 화면)도 저장한다(안드로이드 11 이상, 접근성 '화면 캡처' 권한). 재생할 때는 **화면이 전환되고 누를 자리(쿠폰 버튼 등)가 기록 때처럼 보이는 순간** 바로 누른다 — 화면 전체의 로딩(배너·이미지·타이머)이 끝나길 기다리지 않는다: ① 앞 화면에서 전환됐고(앞 화면과 90% 이상 같으면 아직 안 넘어간 것으로 보고 누르지 않음) ② 누를 자리 주변이 85% 이상 같고 ③ 전체가 60% 이상 같으면 **한 번만 봐도** 누른다(전체 90%+주변 85%+면 전환 확인 없이도 즉시). 오래 걸려도 안 눌리는 일이 없게 3초 넘으면 전체 50%, 8초 넘으면 40%까지 완화하고, 그 정도에 못 미치면 연속 2회(80%/75%) 확인. 선착순은 서버 렉으로 화면이 한참 늦게 뜰 수 있어서, 전환되기 전 화면에서는 **최대 1분까지 계속 기다린다**(대기 중 2초마다 로그에 일치율). 마지막 이동 뒤 쿠폰 화면도 같은 방식(전환됐고 전체 60%+). 로딩 뒤 저절로 스크롤되는 화면이면 스크롤이 끝나 기록 때와 같은 화면이 된 다음에 누른다. 스크롤(스와이프)도 마찬가지로 그 화면이 뜬 뒤에 한다. 앱 첫 화면도 앱이 뜨는 동안 미리 확인해 두므로 정각에 이미 맞으면 지연 없음. **실행 중 터치 잠금 + 긴급 정지**: 앱을 여는 순간(오픈 5초 전)부터 실행이 끝날 때까지 투명 창이 화면 전체의 사용자 터치를 막고(화면 모습은 그대로라 기준 화면 비교에 영향 없음), 오른쪽 위에 빨간 **[■ 긴급 정지]** 버튼이 뜬다 — 누르면 매크로가 즉시 멈추고 잠금도 풀린다(예약이 켜져 있으면 다음 회차는 계속, 모두 끄려면 앱에서 [예약 중지]). 매크로 자신의 탭/스크롤을 보내는 순간(약 0.1~0.5초)에만 잠금 창이 터치를 통과시키고, 그 동작이 버튼 자리에 닿을 때는 버튼도 그 순간만 통과시킨다. **매크로 동작이 잠금 창에 막히는지 스스로 확인한다**: 막혔으면(통과 설정이 입력 시스템에 닿기 전에 동작이 도착) 통과 대기 시간을 늘려 같은 동작을 다시 보내고, 2번 넘게 막히는 기기에서는 잠금을 포기하고 매크로를 우선한다(긴급 정지 버튼은 유지, 로그에 안내). 매크로 탭이 긴급 정지 버튼에 닿은 경우도 정지로 취급하지 않고 무시한다. 정각 첫 탭은 늦지 않도록 정각 직전에 미리 통과 상태로 열어 둔다. 오픈까지 한참 남은 대기 중에는 잠그지 않는다(폰 사용 가능). **스크롤(스와이프)**: 재생 속도는 기록한 속도의 **2배**(고급 설정 '스크롤 속도', 0.5~8, 1=기록한 속도 그대로)이되 **스크롤 거리는 그대로**: 스크롤 거리는 손가락이 움직인 거리 + 뗀 뒤 관성(fling)으로 정해지고 관성은 뗄 때 속도가 정하므로, 손가락 이동은 배율만큼 빠르게 하고 **손가락을 떼기 직전 0.1초는 기록한 평균 속도 그대로** 움직인다(두 구간을 손가락을 떼지 않고 이어 붙여 전송). 그래서 빨라져도 관성이 1배 재생과 같아 같은 거리만큼 스크롤된다. 기록 때 실제로 뗀 속도가 평균과 다르면 거리가 조금 다를 수 있다(그땐 알려 주세요). 스크롤이 끝난 화면은 그 다음 탭이 기준 화면으로 확인한다. 동작(탭/스크롤)은 끝난 뒤에 다음 동작을 보낸다(끝나기 전에 보내면 앞 동작이 취소됨). **정각 지연 최소화**: 기준 화면 해석·첫 화면 확인·앱이 앞에 있는지 확인은 모두 정각 전에 끝내 두고, 정각에는 확인 없이 곧바로 첫 탭만 보낸다(앱을 연 직후부터 화면을 지켜보다 안정이 확인되면 더 읽지 않고 정각까지 쉼). 로그 `첫 동작이 나간 시각: 목표(정각-lead) 대비 Nms` 로 실제 지연을 확인할 수 있고, 계속 늦으면 고급 설정의 '미리 누르기 lead (ms)'(기본 100)를 그만큼 키운다. 기준 화면이 없거나(구버전 기록/캡처 실패/한 색 화면) 앞 단계와 같은 화면인 단계는 시간 기준: ① 기록한 대기 시간(0.3~2.5초)은 항상 기다림(화면이 안 바뀌는 곳 대비) ② 그 사이 화면이 바뀌기 시작했거나 로딩 표시가 떴다면 잠잠해질 때까지(0.5초 변화 없음, 최대 +4초) 더 기다림. 마지막 이동 뒤 쿠폰 선택도 같은 확인. 로그에 `원하는 화면 확인(이동 2/4): 1200ms 대기 · 전체 91% 누를 곳 주변 100%` 처럼 단계마다 남고, 시간 기준 단계는 `화면 확인: N ms 대기 · …` 로 남는다. 기록 후 단계에 ◎ 가 없으면 그 단계는 기준 화면이 저장되지 않은 것(경로를 다시 기록). 글자는 저장하지 않으므로 아이콘/이미지/글자 모두 같은 방식. '닫기' 같은 팝업 버튼만 '없어도 진행'(`?닫기@…`)으로 저장. 기록 중 파란 점 + [■ 기록 끝 (N단계)] 숫자로 기록 여부 확인. 기록 중 터치가 아래 앱에 전달되기까지 약간 느리고, 전달하는 순간(약 0.1초)에는 터치가 기록되지 않는다 — 한 동작씩 천천히. 뒤로가기/홈 제스처는 기록되지 않으므로 누르지 말 것. 앱 화면 구성이 달라지면 다시 기록(예전 방식으로 기록한 경로는 위치·기준 화면이 없으니 다시 기록).
  - **클릭 확인**: 클릭이 나가면 그 자리에 빨간 점이 잠깐 뜸 (이동 단계·팝업 닫기 포함). [찾기만]은 누를 위치에 초록 점만 표시. [고급 설정]에서 끌 수 있음.
  - 쿠폰을 못 찾으면 로그에 이유가 남음(문구가 화면에 없음 / 기준 문구가 안 보임 / 읽히는 문구 목록). 화면을 아래로 당겨 새로고침하는 동작은 예약 실행에서만 한다. 경로를 기록하지 않았다면 예약 실행/즉시 실행도 앱을 다시 시작하지 않고 지금 화면에서 이어서 진행.
  - 문구가 안 맞으면: [고급 설정 → 진단 도구 → 5초 뒤 화면 요소 보기] → [로그]에서 실제 문구 확인 → [고급 설정]에 반영
  - 메인 화면 버튼은 두 개: **[▶ 예약 시작]**(다음 회차 시각에 맞춰 대기 후 클릭) / **[⚡ 즉시 실행 (테스트)]**(오픈 시각을 기다리지 않고 예약과 같은 순서로 지금 연습 — 기록한 경로가 있으면 **앱 실행(첫 화면) → 5초 기다림 → 경로 이동 → 쿠폰 선택**(5초는 '앱 실행 시점'), 경로가 없으면 지금 보던 화면에서 바로 시도. 상시 받을 수 있는 쿠폰으로 연습). 클릭 없이 위치만 확인하는 [찾기만]은 고급 설정의 진단 도구에 있음.
  - 회차 시각 직후 2분 이내에 시작하면 그 회차를 바로 시도, 그 이후엔 다음 회차로 넘어감
- **설정 자동 저장**: 이벤트(쿠팡/N+)별로 따로 저장되고, 앱을 닫거나 업데이트해도 유지됨. [고급 설정 → 이 이벤트 설정 초기화]로 기본값 복원.
- **앱 내 업데이트**: 앱 시작 시 자동 확인 + [업데이트 확인] 버튼 → 새 빌드가 있으면 변경 내용(커밋 메시지) 표시 → [업데이트] → 다운로드 → 설치 확인 화면
  - 배포 방식: push 시 CI 가 서명된 APK 를 GitHub Release(`build-<번호>`, 최근 5개 유지)로 게시. 앱은 최신 릴리스의 빌드 번호(=versionCode)와 비교.
  - **서명 키는 CI가 알아서 관리**: 첫 빌드에서 키를 만들어 저장소의 **비공개 초안 릴리스**(`signing-key (private)`, 쓰기 권한자만 보임)에 보관하고 이후 빌드마다 같은 키를 복원해 서명한다. 이 초안은 **삭제/게시하지 말 것**(삭제하면 이후 업데이트 불가). 원하면 Secrets(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`)로 직접 지정할 수도 있다(Secrets 우선).
  - **처음 한 번만**: 이전에 설치한 APK(Actions 아티팩트)는 서명 키가 매번 달라서 덮어쓸 수 없다 → 앱 삭제 후 [릴리스 페이지](https://github.com/mbt030809-debug/ticketing/releases/latest)의 APK 로 새로 설치. 그 뒤로는 앱 안에서 업데이트된다. (삭제하면 저장된 설정이 지워짐)
  - 업데이트 실패 시 원인(서명 불일치/저장 공간/차단 등)을 토스트와 로그에 풀어서 표시.
  - 저장소가 비공개로 바뀌면 인증 없는 조회가 막혀 앱 내 업데이트가 동작하지 않음.
  - 작업(예약) 실행 중에는 업데이트 불가.
- 동작: 앱 실행 → 이동 단계 클릭 → NTP 보정 후 오픈 시각 대기 → 버튼 반복 클릭 → 성공/소진 문구·토스트 감지 → 알림
- 한계: 이미지/캔버스 버튼은 문구 매칭이 안 되므로 [위치로 찍기]를 사용(화면이 바뀌면 다시 지정 필요). 서버 병목·재고 소진은 속도로 해결 불가.

## Python (PC + ADB)

폰 앱을 PC 에서 ADB/uiautomator2 로 제어한다.

## 전제 / 주의
- 본인 계정 1개, 본인 실기기. 에뮬레이터는 앱이 막을 수 있음 (우회 기능 없음).
- 캡차·본인인증 화면이 뜨면 수동 처리 (자동 우회 없음).
- 쿠팡·네이버 약관상 자동화 제한 가능 → 계정 제재 책임은 사용자 몫.
- 이 저장소의 selector/문구/경로는 **placeholder**. 실기기에서 확인해서 채워야 동작함.

## 준비 (PC)
1. 폰: 개발자 옵션 → USB 디버깅 ON (또는 무선 디버깅), 쿠팡/N+ 앱 로그인 상태 유지, 화면 자동 꺼짐 해제
2. PC: `adb` 설치, `pip install -r requirements.txt`
3. `adb devices` 로 연결 확인 (여러 대면 `--serial`)

## 사용
```bash
python -m ticketing ntp                          # PC 시계 오차 확인
python -m ticketing packages naver               # N+ 앱 패키지명 찾기
python -m ticketing inspect --clickable          # 현재 화면 요소 → selector 작성용
# config/events_20261102.yaml 편집 (package, pre_steps, target, 결과 문구, open_at)
python -m ticketing run config/events_20261102.yaml --event coupang_wowday --dry-run   # 타겟 탐색만
python -m ticketing run config/events_20261102.yaml --event coupang_wowday --now       # 리허설 (즉시 클릭)
python -m ticketing run config/events_20261102.yaml --event coupang_wowday             # 본 실행 (오픈 시각 대기)
```

## 설정 요령
- `lead_ms`: 탭 지연 보정. 리허설 로그로 조정 (너무 크면 오픈 전 클릭).
- 타겟 selector 가 오픈 전 버튼("오픈 예정")과 겹치지 않게 지정 → 활성 버튼 문구만 매칭.
- 결과 문구(`success_texts` 등) 미설정 시 클릭 1회 후 종료.
- 스크린샷/로그: `logs/<이벤트>_<상태>_<YYYYMMDD>_<HHMMSS>.png`
- 알림: 터미널 벨, `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` 설정 시 텔레그램

## 검증/디버깅 (수정할 때마다)
- 푸시마다 CI(`build-apk`)가 단위 테스트 + 릴리스 빌드 + lint(참고용)를 돌리고, 작업 요약에 테스트 개수/실패와 lint 오류 수를 표시한다.
- 실행 흐름은 `Flow.plan` 으로 분리해 시나리오 테스트(`FlowTest`)로 고정: 즉시 실행이 예약과 같은 `앱 실행 → 5초 대기 → 경로 이동` 을 따르는지, 화면이 다 바뀐 뒤에 다음을 누르는지(`StepSettleTest`), 테스트 중 화면을 당기지 않는지, 예약 흐름이 `오픈 5초 전 앱 실행 → 정각 경로 이동`인지 등. 흐름을 바꾸면 이 테스트부터 갱신한다.
- 쿠폰 카드 탐색/위치 형식/알람 계산/로딩 안정 판정도 각각 단위 테스트가 있다.
- 폰에서 문제가 생기면 [로그 → 디버그 리포트 복사]: 앱 버전·기기·접근성 상태·현재 설정(경로·쿠폰·시각)·최근 로그가 한 번에 복사된다.

## 쿠폰 선택 속도 (정각 이동 흐름)
- 오픈 5초 전 앱 실행 → 정각 경로 이동 → **이미지/카드가 화면에 뜨는 즉시 탭**. 마지막 이동 직후 별도 로딩 대기 없이 클릭 루프가 바로 시작되고, 대상이 아직 안 보이면 60ms 간격으로 확인한다.
- 결과 판별용 '기준 화면'은 탭 **전**에 화면 전체를 읽지 않고, 첫 탭을 보낸 직후 결과 문구(성공/이미/소진)가 몇 개 보이는지만 조회한다(전체 읽기 대비 훨씬 가볍다).
- 이미지 카드는 [위치로 찍기]로 지정한 '바로 위 글자(기준) + 상대 위치'가 화면에 보이는 순간 그 좌표를 탭한다. 기준 글자가 없으면 화면 비율 좌표를 정각 이동 직후부터 바로 탭한다.
